# Builder Hub 上传与发布

## 1. 准备登录态

发布只由主 Agent 操作浏览器。如果环境中已安装 `kevin-cookie-skill`，先读取它并按其说明检查登录态和取得认证 Profile；不要假设每位安装者都有该 Skill。

已取得认证 Profile 时，用唯一命名 session 启动可用的浏览器自动化工具。源浏览器运行中时禁止同步 Profile。没有 Cookie Skill、登录态过期或创作者后台仍要求登录时，打开有头浏览器，让用户本人扫码、输入验证码或完成验证；不要索取账号密码，不要代填验证码。

## 2. 先核账号和已有工具

进入 `https://creator.xiaohongshu.com/` 后回读显示账号。进入 Builder Hub 的“小工具”，列出现有名称、版本和状态。

- 已有同名工具：默认走“更新版本”，不要重复创建。
- 新工具：点“上传小工具”。
- 账号不对：立即停止。

## 3. 执行官方 Skill 门禁

打开新建或更新页面，读取“第一步：调整为符合小红书规范的代码格式”的当前完整口令。按 [official-skill-gate.md](official-skill-gate.md) 下载、读取并执行当期官方 Skill，再执行本 Skill 的本地校验。

这一步由 Agent 完成，不要求用户复制口令、下载或运行命令。官方与本地检查没有同时达到 error 为 0 时，不进入上传。

## 4. 上传表单

当前新建表单包含：

- 小工具名称
- 一句话功能描述
- 方形 PNG/JPG 图标与裁剪确认
- ZIP
- 语义化版本号，初版通常 `1.0.0`
- 权限声明：不需要、相册、摄像头、麦克风
- 小工具服务协议确认

名称和描述使用用户确认的产品事实，不临时改成夸张文案。默认选择“不需要权限”；源码确实调用允许的端 API 时才选择相应权限。

权限按实际调用映射：

- 只展示内容、筛选、计算、Canvas 或本地游戏：不需要权限。
- 调用 `saveImageToPhotosAlbum`：声明“相册照片与视频”，并在真机由用户主动点击验证保存成功和拒绝授权两种结果。
- 调用摄像头：声明“设备摄像头”，首次授权、拒绝和再次进入都要真机验证。
- 调用麦克风：声明“设备麦克风”，首次授权、拒绝和录音结束都要真机验证。
- `writeTempFile` 只写容器临时文件时不自动等同相册权限；它后续传给哪个端能力，就按该能力声明。
- `postNote` 属于发布页跳转，不等同于相册、摄像头或麦克风；仍需真机确认平台是否另有授权提示。

更新已有工具默认升 patch 版本。内容或样式更新可从 `1.0.0` 到 `1.0.1`；新增权限、核心流程变化或不兼容调整时先问用户版本策略。

## 5. 模拟器验收

ZIP 上传后先检查 Builder Hub 模拟器：

- 首屏能渲染
- 核心按钮可点
- 页面、筛选、详情和返回可用
- 本地图片与字体正常
- 无控制台运行错误

模拟器里能出现站外链接不代表允许发布。上传前的离线校验仍是门禁。

## 6. 协议和提交

打开当次页面上的服务协议并检查是否更新。把名称、版本、权限和包摘要告诉用户。协议由用户本人确认；用户完成勾选后，才点击发布或让用户自己点击。

提交摘要还要列出二维码目的地。指向站外网址、微信或其他平台时，明确说明内容审核可能判定为导流；用户未确认该风险时不提交。

用户已经亲自点击发布时，不重复提交，直接回列表读取状态。

## 7. 回读状态

提交后回到小工具列表，按页面原文报告：

- `审核中` 且有 `撤回`：提交成功，等待审核。
- `已发布` 且有 `下架/编辑/更新版本`：审核通过并上线。
- `审核不通过/需修改`：读取完整原因，截图留证，修改前先与用户确认会改变什么。

同时回读名称、描述、版本和发布账号，保存状态截图。不要把“审核中”写成“已上线”。

## 8. 发布后的下一步

审核通过以后，小工具还需要在发布笔记时通过“添加组件 → 小工具”挂载，用户才能从笔记直接进入。挂载或发布笔记属于另一项外部写入，必须单独得到授权。
