# 创建与改造工作流

## 1. 先拆真实依赖

读取项目入口、构建配置、页面、路由、数据层、网络调用、浏览器能力和品牌素材。把功能分成三类：

- 直接保留：纯前端交互、本地数据、Canvas/WebGL、本地媒体、筛选、计算和离线游戏。
- 改成静态：数据库读取、价格表、榜单、内容列表、服务端渲染结果。构建时写入真实快照。
- 必须删除或让用户决策：登录、支付、联网 AI、实时数据、在线人数、统计心跳、外链、联机、远程媒体、WASM 和 Worker。

不把删掉的功能换成假按钮、假结果或静默兜底。

## 2. 一轮关键提问

只问项目检查后仍未知的内容，最多五问。可直接使用下面的短版：

1. 这个小工具只让用户完成哪一件事？
2. 这些联网功能准备怎么处理：删除，还是改成发布时快照？
3. 数据多久更新一次，能否每次更新时重新发版本？
4. 需要相册、摄像头或麦克风吗？推荐默认不需要。
5. 这是新建还是更新已有小工具，名称、简介、图标和发布账号用哪一套？

问题给出推荐选项，并说明选择会删除或改变什么。用户已明确的内容不重复问。

## 3. 项目结构

默认在原仓库创建 `xhs-minitool/`，让主站继续独立运行：

```text
xhs-minitool/
  index.html
  package.json
  vite.config.ts
  src/
  public/
  scripts/
  dist/                         构建产物，不提交
  <name>-xhs-tool.zip           上传包，通常不提交
  icon.png                      Builder Hub 图标
  cover.png                     Builder Hub 封面
```

共享业务数据应在构建时从主项目唯一真相源导入。无法直接导入时，生成一次性的 JSON 快照并记录生成命令，不让两份手写数据长期漂移。

Vite 项目使用 `base: "./"`。优先生成固定的 `assets/main.js` 与 `assets/style.css`、关闭 sourcemap，并避免不必要的动态分包。框架不限，但包必须脱离开发服务器运行。

## 4. 本地门禁

构建完成后运行：

```powershell
python -X utf8 "<本 Skill 目录>\scripts\validate_package.py" <zip路径> --max-bytes <上传页当前上限>
```

校验脚本 error 必须为 0。warning 要人工解释，不能直接忽略。

继续做这些验证：

- ZIP 完整性和根目录 `index.html`
- 生产 HTML 的 JS/CSS/图片全部 200
- 浏览器控制台和页面错误为空
- 390×844 与 320×568 没有整页横向溢出
- 触控目标至少 44px
- 首屏、核心流程、空结果、返回和详情可用
- 二维码从最终整页截图中能实际解码，并记录它是否指向站外网址、微信或其他平台
- 真实中文、长名称和极端数据不会截断关键意思

## 5. 让用户看成品

至少提供首屏、核心结果页和详情/结束页截图。用人话说明：

- 保留了什么
- 删除或静态化了什么
- 权限是什么
- 包体多大
- 哪些行为只能等 Builder Hub 真机验证

用户说不满意就继续改。不要一边调视觉一边上传多个版本。用户明确满意后，重新构建一次最终 ZIP，再进入 [Builder Hub 官方 Skill 门禁](official-skill-gate.md)。官方门禁若改变可见成品，必须重新预览确认。

项目文档与平台规则打架时，不按“尽量不改”继续保留禁用能力。明确指出冲突，把外链改成纯文字、把实时数据改成真实快照等方案交给用户确认；确认前不上传。

## 6. 图标和封面

优先复用项目已有品牌图形。产品图标表现产品，不拿作者头像代替产品图标。矢量图可以确定性渲染成方形 PNG，不用生成模型重画品牌字形。

图标和封面都要在实际上传裁剪框里检查。不要只看本地原图；平台裁剪可能放大、截边或改变安全区。
