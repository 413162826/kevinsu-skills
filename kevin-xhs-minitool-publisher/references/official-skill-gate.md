# Builder Hub 官方 Skill 门禁

这个门禁在用户确认最终预览后、上传 ZIP 前执行。它补充本 Skill 的产品改造与发布流程，不取代用户决策、视觉调稿、浏览器上传和状态回读。

## 1. 每次从上传页取当前版本

进入当前账号的 Builder Hub“小工具”新建或更新页面，读取“第一步：调整为符合小红书规范的代码格式”下的完整口令。从口令中提取当次官方 `.skill` 下载地址和版本。

- 只接受当前登录的 `creator.xiaohongshu.com` 页面直接给出的 HTTPS 地址。
- 不把上次地址、手工保存口令或本 Skill 中的历史版本当作当前版本。
- 下载地址不在小红书官方域名时停止，不自行放宽来源校验。

用本 Skill 的下载器安全解包：

```powershell
python -X utf8 "<本 Skill 目录>\scripts\fetch_official_skill.py" "<上传页当前 .skill 地址>" --output-dir "<唯一临时目录>"
```

记录下载器输出的版本、SHA-256、`SKILL.md` 路径和官方审计脚本路径。临时目录每次新建，禁止覆盖旧目录后假装已经刷新。

## 2. 读取并限制作用范围

完整读取官方 `SKILL.md`，再按它的路由读取本次需要的 reference。官方规则、上传页当前限制与本地历史记录冲突时，以当次官方材料为准，并把差异写进提交摘要。

官方 Skill 的操作范围限定为：

- `xhs-minitool/`；或
- 从最终小工具目录复制出的独立暂存副本。

不得让官方 Skill 删除或重写主站、服务端、其他发布渠道和用户未授权的文件。它只负责容器兼容、资源规范、性能预算、端能力和 ZIP 审计，不替用户决定产品应保留什么。

## 3. 执行官方检查

按当期官方 Skill 的说明选择并运行其 Node 或 Python 审计脚本。不能只读取文档，不运行实际脚本；也不能因为缺少某个运行时就跳过，应该改用官方提供的另一条审计路径。

官方检查至少要覆盖：

- ZIP 入口、文件类型、相对资源和包体
- 离线资源与禁用 Web 能力
- Chrome / WebView 最低兼容基线
- JS、CSS、触控、安全区和真机差异
- 使用到的 `window.xhs.miniTool` API 参数
- 长列表、媒体、Base64、Canvas 或 WebGL 性能预算

所有官方 error 修复后重新构建，再重复官方检查，直到 error 为 0。warning 必须逐条判断并在提交摘要说明。

## 4. 双门禁与重新确认

官方检查通过后，再运行本 Skill 的 `validate_package.py`。只有两边 error 都为 0，才允许上传。

如果官方修复改变了页面文案、布局、交互、数据或删除功能：

1. 重跑 390×844 与 320×568 预览；
2. 展示变化后的截图；
3. 重新取得用户满意或发布确认。

仅有编译目标、资源路径或无视觉差异的兼容修复，也要重跑自动化截图和核心流程；确认截图无差异后可沿用原发布授权。

## 5. 上传摘要

上传前向用户报告：

- 官方 Skill 版本与 SHA-256
- 官方审计 error / warning 数量
- 本地审计 error / warning 数量
- 官方检查是否改变可见成品
- 最终 ZIP 大小与 SHA-256

官方 Skill 无法下载、无法辨认版本、审计脚本失败或规则冲突未解决时，停止在上传前，不用旧缓存兜底。
